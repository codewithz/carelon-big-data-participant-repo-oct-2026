What is a join, and why do we need one?

A database keeps each kind of fact in its own table: people in one, departments in another, projects in a third. A join is the instruction that lines two tables up so you can read them as one. To see why the data is split in the first place, try changing a department name below.

Write each fact once

A department name stored in one row cannot disagree with itself. Fifty thousand call records can all point at the same queue row.

Fix it in one place

Rename a queue or move an agent to a new team with one edit. Every report that reads the data sees the change.

Join when you need the words

A report that says dept_id 10 is useless to a manager. A join looks up 10 and shows Sales, only when you ask, and without changing the stored data.

In your contact centre data the same thing happens. Each call stores a queue_id and an agent_id. The words Billing and Agent 07 live in the queues and agents tables. Every KPI report by queue or by agent starts with a join.

Three ways joins go wrong

    

      

        Missing ON
        
Every row meets every row


SELECT e.emp_name, d.dept_name
FROM employees e
CROSS JOIN departments d;

        
5 employees times 4 departments is 20 rows. In an old-style query with a comma between tables and no WHERE, you get the same thing by accident. If a result has far more rows than either table, look for a missing condition.

      

      

        Silent loss
        
INNER JOIN drops without a word


SELECT count(*)
FROM employees e
JOIN departments d
  ON d.dept_id = e.dept_id;
-- 4, but there are 5 employees

        
Dana's dept_id is NULL. NULL is not equal to anything, not even another NULL, so Dana never matches. Nothing warns you. Compare the count with the plain table before you trust a report.

      

      

        Repeats
        
One-to-many repeats the one


SELECT d.dept_name, e.emp_name
FROM departments d
LEFT JOIN employees e
  ON e.dept_id = d.dept_id;
-- Sales appears twice

        
Sales has two employees, so the Sales row is repeated, once per employee. Adding up a department-level number after this join counts it twice. Join, then check the row count.

      

    

  


  
  

    
Which join do I use?

    

      

        
JoinKeepsUse it when

        
          
INNER JOINOnly rows with a partner on both sidesYou only care about complete pairs

          
LEFT JOINEvery row from the first table, NULL where no partnerYou need every call, agent or project, even those with missing details

          
RIGHT JOINEvery row from the second tableRare. Swap the table order and use LEFT JOIN instead

          
FULL OUTER JOINEvery row from both tablesComparing two lists to find what is missing from each

          
CROSS JOINEvery pairingBuilding a grid, such as every queue for every hour
